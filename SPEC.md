# ТЗ: «Картотека студии» — Telegram Mini App + бот

Документ для Claude Code. Положить в корень нового репозитория как `SPEC.md`, в `CLAUDE.md` добавить строку «Требования см. в SPEC.md».

## 1. Контекст

Заказчица — владелица небольшой танцевальной студии (парные танцы: танго, румба, женский стиль, группы для начинающих, воскресные практики). Сейчас помнит всё в голове и в переписках. Ей нужна простая «картотека», а не полноценная CRM.

Её слова (суть голосового сообщения):
- Нужно учитывать 50–70 активных людей (девочек и мальчиков), основную часть данных она готова вносить вручную.
- Напоминания: кто-то уходит в декрет или уезжает и пишет «вернусь в ноябре/августе» — система должна напомнить написать этому человеку.
- Оплаты: перед тем как писать расписание на неделю, нужно вспомнить, кто какое занятие и на какие дни оплатил. Часто оплата приходит раньше, чем появляется расписание.
- Напоминание о неоплаченных занятиях.
- Спрос на направления: «кто просил женский стиль», «кто ждёт румбу/танго» — чтобы собрать новую группу, в том числе группу для начинающих.
- Боль: отмены в последний момент. На практиках важен баланс партнёров (лидеры и партнёрши поровну); три отказа в воскресенье оставили двоих мальчиков без пар.
- Не нужны: онлайн-запись, сложные расчёты, сотни страниц. Нужна минимальная автоматизация и низкая цена.

Дополнительные пожелания заказчика (разработчика): календарь для наглядности и интеграция с календарём телефона.

Продукт состоит из двух частей, которые работают вместе:
1. **Telegram Mini App** (веб-интерфейс внутри Telegram): календарь, люди, оплаты, направления.
2. **Telegram-бот**: утренняя сводка, напоминания, быстрый ввод обычными сообщениями, кнопка открытия Mini App.

Пользователи: владелица студии и, возможно, 1–2 помощника. Язык интерфейса — русский. Основное устройство — телефон.

## 2. Принятые допущения (изменить, если заказчица скажет иначе)

| Вопрос | Допущение по умолчанию |
|---|---|
| Модель оплаты | Оплата записывается за конкретное направление на неделю или на конкретный день. Дата занятия необязательна. Абонементов и остатка занятий в первой версии нет |
| Отмена в последний момент | Отдельный статус оплаты `late_cancel` (оплата не возвращается и не переносится). Перенос как кредит — вне первой версии |
| Занятия | Постоянное недельное расписание (шаблоны) плюс разовые события, например практика |
| Роли | У человека есть необязательная роль `lead` / `follow` (лидер / партнёрша); используется для баланса на практиках |
| Календарь телефона | Односторонняя подписка по ссылке `.ics`. Двусторонней синхронизации нет |
| Напоминания | Сообщениями бота в Telegram. Время утренней сводки настраивается, по умолчанию 09:00 по Москве |
| Деньги | Рубли, целые числа |

Вопросы к заказчице, которые стоит уточнить до фазы 2: как платят (за занятие, месяц, абонемент); в какие сроки отмена считается «в последний момент»; какой календарь использует (iPhone или Google); сколько помощников.

## 3. Объём первой версии (MVP)

### 3.1 Люди
- Карточка: имя, контакт (телефон или Telegram), статус (`active` занимается / `pause` пауза / `left` не ходит), роль (необязательно), заметка.
- Для статуса `pause`: месяц возвращения (`return_on`, `YYYY-MM`) и заметка.
- Теги «занимается» (направления) и «ждёт» (направления).
- Список с поиском по имени, заметке и контакту, фильтрами по статусу и направлению.
- Создание человека «на лету» при вводе оплаты, если имени нет в списке.

### 3.2 Направления
- Справочник: Женский стиль, Румба, Танго, Для начинающих, Практика. Можно добавлять свои.
- Экран «Направления»: по каждому — кто занимается и кто ждёт (счётчики и имена). Тап по имени открывает карточку.

### 3.3 Занятия и календарь
- Шаблон занятия: направление, день недели, время, место (необязательно), цена по умолчанию.
- Разовое занятие: дата, время, направление.
- Календарь-месяц: точки у дней с занятиями; красная точка — есть неоплаченные. Тап по дню показывает занятия с «оплатили X из Y».
- Экран недели: удобен при составлении расписания (кто оплатил за эту неделю по каждому направлению).
- Для практики показывать баланс ролей: сколько лидеров и партнёрш записано и сколько не хватает.

### 3.4 Оплаты
- Запись: человек, направление, неделя или день, сумма, статус (`paid` / `unpaid` / `late_cancel`), заметка.
- Быстрая отметка «Оплатил» одним тапом из списка неоплаченных.
- Сводка за неделю: оплатили, ждём, отмены, сумма.

### 3.5 Экран «Сегодня»
- Кому написать (статус `pause`, `return_on` в текущем или следующем месяце), неоплаченные занятия (просроченные выделены), краткая сводка «ждут занятий».

### 3.6 Бот
- Команда `/start` открывает Mini App (кнопка меню и inline-кнопка).
- Утренняя сводка по расписанию: кому написать, кто не оплатил, ближайшие занятия. Под сообщением кнопки действий («Написала», «Отложить на неделю», «Все неоплаченные», «Кто чего ждёт»).
- Быстрый ввод обычным сообщением (см. 6), с подтверждением и кнопками «Отменить» / «Изменить».
- Команды `/сегодня`, `/неделя`, `/ждут`.

### 3.7 Календарь телефона
- Приватная ссылка на `.ics` (подписка, токен в адресе), в ней занятия на ближайшие 3 месяца. Кнопка «Подключить» показывает ссылку и инструкцию для iPhone и Google Календаря.

### 3.8 Доступ
- Доступ только по списку разрешённых Telegram ID. Остальным — сообщение «Нет доступа».
- Роли: `owner` (всё), `assistant` (всё, кроме удаления и управления доступом).

## 4. Вне объёма первой версии
Онлайн-запись клиентов, оплата внутри приложения, абонементы и остаток занятий, перенос оплаты как кредит, двусторонняя синхронизация с Google Календарём, рассылка сообщений клиентам от имени бота (бот пишет только владелице и помощникам), мультистудии.

## 5. Модель данных (черновик)

```
user            id, tg_id (unique), name, role(owner|assistant), created_at
client          id, name, contact, status(active|pause|left), role(lead|follow|null),
                return_on (YYYY-MM|null), note, created_at, updated_at
direction       id, name (unique), sort
client_direction  client_id, direction_id, kind(attends|wants)   -- составной ключ
lesson_template id, direction_id, weekday(0-6), start_time, duration_min, place, default_price, active
lesson          id, direction_id, date, start_time, duration_min, place, template_id|null, note
payment         id, client_id, direction_id, lesson_id|null, week_start (date),
                lesson_date|null, amount, status(paid|unpaid|late_cancel), note, created_at, updated_at
reminder_log    id, kind, ref_id, sent_at          -- чтобы не слать одно и то же дважды
settings        key, value                         -- время сводки, токен календаря, часовой пояс
```

Правила:
- `payment.week_start` обязателен; `lesson_id` и `lesson_date` необязательны (оплата может прийти раньше расписания). Когда расписание появляется, оплата привязывается к занятию по направлению и неделе.
- Удаление клиента — «мягкое» (`status = left` и скрытие); физическое удаление только владельцем и с подтверждением.
- Все даты и время — в `Europe/Moscow`.

## 6. Быстрый ввод в боте

Сначала простой разбор по правилам, без ИИ. Примеры:

| Сообщение | Действие |
|---|---|
| `Динара оплатила танго 1500` | оплата: клиент, направление, сумма; неделя — текущая или ближайшая будущая, уточнить кнопкой |
| `Анна, румба, 1500, неделя 26.10` | то же с явной неделей |
| `Оля вернётся в декабре` | клиент → `pause`, `return_on = ближайший декабрь`, напоминание за 5 дней до |
| `Света ждёт танго` | тег «ждёт: Танго» |
| `Практика вс: Игорь, Анна, Динара, Света` | список записавшихся на практику с подсчётом ролей |

Если разбор неуверенный, бот уточняет кнопками, а не угадывает. Любая запись подтверждается сообщением с кнопками «Отменить» и «Изменить». Имена сопоставляются с существующими клиентами по началу слова без учёта регистра и форм; при неоднозначности бот предлагает варианты.

Вторая фаза (по желанию): разбор свободного текста через LLM-API с тем же подтверждением. Не включать в MVP.

## 7. Дизайн

Макеты уже сделаны на холсте Claude Design «Картотека студии: сайт и бот» (4 экрана и календарь). Если холст недоступен, ориентироваться на описание:

- **Сайт A** — светлая тема, списки, нижнее меню (Сегодня, Календарь, Люди, Оплаты, Танцы). Фон `#F5F4F8`, текст `#1E1A2B`, акцент `#B3204F`, успех `#1D7A63`, предупреждение `#9A5600`. Шрифты Onest и Unbounded.
- **Сайт B** — тёмная тема, быстрая строка записи внизу, крупная цифра «дел на сегодня».
- **Бот A** — кнопки; **бот B** — свободные сообщения.

Заказчица выберет вариант. До этого строить интерфейс на токенах темы так, чтобы вариант A/B менялся заменой переменных.

Требования к интерфейсу:
- Mobile-first, ширина 360–430 px, элементы касания не меньше 44 px.
- Цвета и тема берутся из Telegram (`Telegram.WebApp.themeParams` и `colorScheme`), своя палитра — только акцент.
- Главное действие экрана — через `Telegram.WebApp.MainButton`; кнопка «Назад» — через `BackButton`.
- Тактильный отклик (`HapticFeedback`) при отметке «Оплатил».
- Подтверждение удаления внутри страницы; `alert` и `confirm` не использовать.
- Пустые состояния с объяснением и действием (например, «Пока никого нет. Добавьте первого человека»).
- Контраст текста не ниже 4.5:1 в обеих темах.

## 8. Рекомендуемый технический стек (можно заменить с обоснованием)

- **Язык:** TypeScript, Node.js 20+.
- **Бот:** grammY.
- **Сервер:** Fastify; REST JSON API; проверка Telegram `initData` (HMAC-SHA256 с токеном бота), срок жизни подписи ограничить.
- **Mini App:** Vite + React (или Preact), без тяжёлых UI-библиотек; календарь написать самому (простая сетка).
- **БД:** SQLite (файл) через Drizzle или Kysely; миграции в репозитории. Для 50–70 клиентов достаточно; запланировать ежедневную копию файла.
- **Планировщик:** `node-cron` в том же процессе (утренняя сводка, напоминания о возвращении).
- **`.ics`:** библиотека `ics` или ручная генерация, эндпоинт `/cal/<token>.ics`.
- **Развёртывание:** Docker, один небольшой VPS, Caddy с автоматическим HTTPS, домен или поддомен.
- **Тесты:** Vitest для разбора сообщений, правил напоминаний и проверки `initData`.

Все секреты (токен бота, ключи) — в переменных окружения, в репозиторий не попадают; приложить `.env.example`.

## 9. Этапы

1. **Каркас.** Репозиторий, Docker, бот отвечает на `/start`, Mini App открывается, проверка `initData` и список разрешённых ID работают.
2. **Люди, направления, оплаты.** БД и API, экраны «Люди», «Направления», «Оплаты», экран «Сегодня». Загрузка демо-данных одной командой для показа заказчице.
3. **Занятия и календарь.** Шаблоны и разовые занятия, календарь месяца и недели, баланс ролей на практике.
4. **Бот-напоминания.** Утренняя сводка, кнопки действий, команды, журнал отправленного.
5. **Быстрый ввод.** Разбор сообщений из раздела 6 с подтверждением.
6. **Календарь телефона.** Эндпоинт `.ics` и экран «Подключить».
7. **Доводка.** Выбранный заказчицей вариант оформления, бэкапы, README с инструкцией развёртывания.

После каждого этапа — рабочая версия, которую можно показать заказчице.

## 10. Критерии приёмки

- Человек с паузой и месяцем возвращения появляется в «Сегодня» → «Написать» в нужный месяц, и бот упоминает его в утренней сводке.
- Оплата, записанная до появления расписания, видна в разделе недели и привязывается к занятию после его создания.
- Неоплаченные занятия отображаются в «Сегодня», просроченные выделены; «Оплатил» меняет статус одним тапом.
- По каждому направлению видно, кто занимается и кто ждёт.
- На практике показывается баланс лидеров и партнёрш.
- Сообщение `Динара оплатила танго 1500` создаёт оплату после подтверждения; кнопка «Отменить» откатывает запись.
- Неразрешённый Telegram-аккаунт не получает данных ни через Mini App, ни через API.
- Подписка на `.ics` показывает занятия на iPhone и в Google Календаре и обновляется при изменении расписания.
- Интерфейс читаем в светлой и тёмной темах Telegram, без горизонтальной прокрутки на ширине 360 px.
- Повторный запуск не дублирует напоминания (журнал отправленного).

## 11. Безопасность и данные

- Данные клиентов — персональные (имена, контакты). Хранить только необходимое, не передавать третьим лицам, не логировать содержимое заметок.
- Доступ по списку Telegram ID; все эндпоинты API проверяют подпись `initData`.
- Токен календаря случайный и длинный, перевыпускается по кнопке.
- Резервная копия БД ежедневно, хранение 14 дней.

## 12. Что уточнить у разработчика перед стартом

1. Где будет размещаться сервис (свой VPS, платформа) и на чьё имя регистрируется домен.
2. Кто создаёт бота через @BotFather и хранит токен.
3. Какой вариант оформления сайта выбран (A или B) и нужен ли календарь на неделю вместо месяца в первой версии.
4. Нужен ли LLM-разбор сообщений (фаза 2) и кто оплачивает API.
